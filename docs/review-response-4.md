# 第4回の改善：学習履歴を次の復習に生かす

目的：正解しただけで理解したと判断せず、回答履歴・自信度・ヒント使用を、次の復習の問題選びに使う。
仕様は `docs/design.md` の 5-1（記録）、5-9（復習で出す問題の選び方）、5-10（日付が変わるとき）。

## 2. 変更した内容
| 変更 | 場所 |
|---|---|
| 問題ごとの優先の理由（誤答 → ヒントで正解 → 意味の問いが違った正解 → 自信がない正解）を回答履歴から決め、復習の2問目に使う | `planner.js` の `needOf`・`seenInfo`・`reviewPicks` |
| 1問目は、つまずいた問題・優先の理由がある問題「以外」の別の問題（同じ理解を別の問題で確かめる） | `planner.js` の `reviewPicks` |
| 採点保留・指定の形と違う答え、解き直しの正解、つまずいた日と同じ日の解説後の正解では、優先を変えない | `planner.js` の `needOf` |
| 別の日に正解すると、その問題の優先は外れる（毎回同じ問題が出続けないように） | 同上 |
| 項目の順：再確認が必要 → 自信がないが残る → それ以外 | `planner.js` の `priorityOf` |
| 項目に問題が1問しかないときは、その問題で確認し、「次回にもちこす内容」に理由を残す（再確認は解消しない） | `planner.js` の `buildReviewSession` |
| 復習の回答に、選んだ理由 `pickWhy` を記録 | `session.js` の `submit` |
| ホームを開いたまま日付が変わったら、画面に戻ったときに描き直す | `app.js` |

**保存形式**：形式（v3）は変えていません。新しい項目 `pickWhy` は、ない場合に「この項目ができる前の記録」と扱うので、移行は不要です。
自信度の項目がない古い記録には値を補わず、「自信がない」とは扱いません。

**変えていないもの**：項目の確認状況・再確認の解消の条件（`mastery.js`）、復習間隔（`scheduler.js`）、採点、画面の構成。

## 4. 残っている制約
- 記録は端末内だけ（端末・ブラウザ間で共有されない。講師はまだリアルタイムに見られない）。
- 自信度は「自信がない」と申告なしの2つだけ。
- 問題が少ない項目では、別の問題で確かめられる回数に限りがある（1問しかない項目は再確認を解消できない）。
- 優先の理由は「次にどの問題を出すか」だけに使い、理解の判定には使っていない。

## 5. 再発防止（変更するときの注意）
- 復習の問題選びは `reviewPicks` に集める。別の選び方を作らない（項目の予定は `scheduler.js`、確認状況は `mastery.js`）。
- 採点保留・指定の形と違う答えを、誤答や正解の根拠に入れない。
- 解説を見たあとの正解を自力正解に数えない。問題の優先を外せるのは別の日の正解だけ。
- `confidence` は `'unsure'` だけを低い自信として扱う。値がない記録に値を補わない。
- vm で読み込んだ配列を `assert.deepEqual` で比べると、内容が同じでも失敗する。文字列にして比べる。
- 変更したら `npm run check` と `node tests/history-e2e.mjs` を実行する。学習の流れが変わったら `node tools/scenario.mjs > docs/learning-examples.txt` で学習例を更新する。
