# 設計メモ（初期版）

## 1. 目的の理解
高校・大学受験に向けた英文法の基礎固めを、生徒が一人で進められるようにするアプリ。
「解説を読んで終わる」「すぐ忘れる」「選べても理由がわからない」「次に何をするか決められない」「復習しない」
を減らすため、**アプリが次の課題を出し、答えを見ずに思い出す機会を、日を空けて繰り返す**。
正解したことと理解したことを区別し、記録は講師がのちに確認できる形で残す。

## 2. 範囲
**初期版で作ったもの**
- 単元「不定詞（基本）」：〜すること／〜するための・〜すべき／〜するために（目的）の3項目
- 初回診断6問（空所補充2・並び替え2・日→英2）、全問回答後に結果と解説
- 類題・復習で間違えたときの確認問題（上限つき）と「基本にもどる」説明
- 解説（正答・訳・「どの部分がどの意味につながるか」）→ 解き直し（同じ問題）→ 類題（別の問題＋理由の選択）
- 意味の確認問題（「何のために」「どの言葉を説明」など、文法用語なしで問う）
- 「自信がない」「ヒントを見る」「わからない」、途中終了と再開
- 確認状況（4段階・根拠つき）、復習予定（ルール）、復習テスト、履歴・復習一覧、問題ごとの過去の回答
- 動作確認用デモモード（別の保存領域・日付を進める）、記録の書き出し（コピー）

**後回し**：正誤判断＋理由選択の問題形式、ほかの単元、講師画面、ログイン・サーバー、AI、音声、長文、ランキング等。
「英定義」は仕様未定のため何も実装していない。

## 3. 技術構成と理由
- **ビルド不要の静的Webアプリ（HTML・CSS・素のJavaScript）**
  - iPad の Safari でリンクを開くだけで動く。アプリストア申請やインストールが不要。
  - 将来スマートフォン・PCでも同じものが使える。
  - 部品が少なく、開発者が替わっても読みやすい。
- **保存は端末内（localStorage）**。サーバー費用ゼロ・ログイン不要で試せる。
  - 限界：端末・ブラウザ間で共有されない／Safariのデータ消去で消える／講師がリアルタイムに見られない。
  - 対策：設定画面から記録を書き出して（コピー）講師に送れる。
- **問題データはプログラムと分離**（`data/infinitive.js`）。`node tools/validate-bank.mjs` で形式チェック。
- 外部サービス・APIキーは使っていない（Google Fonts の文字だけ。読めない場合は端末の文字で表示）。

| 項目 | 仮の前提 |

## 5. 判定ルール（すべてルールのみ、AIなし）
ロジックはすべて表示から独立したファイルにあります（採点 `js/grading.js`、確認状況 `js/mastery.js`、
復習予定 `js/scheduler.js`、出題 `js/planner.js`、学習の進行 `js/session.js`）。

### 5-0. 問題の形式ごとに測るもの
| 形式 | 生徒が答える前に見る情報 | 測るもの | 意味・理由の答えの扱い |
|---|---|---|---|
| 空所補充（診断・日本語つき） | 日本語の文 | 日本語の意味に合う「形」を選べるか | 理由は聞かない |
| 空所補充（類題・復習・英文だけ） | 英文と選択肢（文法的に正しいのは1つだけ） | 文の形から正しい形を選べるか | 訳を見ていないので、意味の問いの答えを**意味理解の根拠**にできる |
| 並び替え（日本語つき） | 日本語の文 | 語順を組み立てられるか | 意味の問いの答えは**参考**（訳を見ているため）。原則として聞かない |
| 日本語→英語（選択肢なし） | 日本語の文 | 自分で文を作れるか | 理由は聞かない |
| 意味の確認（英文だけ） | 英文と質問 | 訳なしで「何のため」「どの言葉を説明」「何の中身」などを読み取れるか | 問題そのものが意味の確認 |

- 日本語訳は、英文だけの問題では答えたあと（解説）で表示します。
- 空所補充の選択肢には、to で始まるものを2つ以上入れます（例：to play／to playing）。正答の位置は毎回入れ替わります。
- 意味の確認問題の誤りの選択肢は、ほかの用法との取り違え（例：「〜するための」を「〜するために」と読む）から作っています。

### 5-1. 1回の回答の記録
| 項目 | 内容 |
|---|---|
| 答えの結果 | 正解 / 不定詞は正解（ほかに小さな直し）/ 指定の形と違う / 不正解 / 採点保留 / 「わからない」 |
| 意味・理由の問い | `reason: null` ＝聞いていない。聞いた場合は選んだ選択肢と正誤（答えの正誤とは別） |
| 自信 | 「自信がない」を押した＝`unsure`、押さなかった＝`none`（申告なし。自信ありとは扱わない）。項目がない古い記録は「記録なし」のまま補わず、`unsure` とは扱わない |
| ヒント | 使ったかどうか |
| 解説後 | 同じ学習回の中で、同じ項目の解説を見たあとの回答か（`afterExplanation`） |
| 日本語訳 | 答える前にその英文の日本語訳を見ていたか（`translationShown`） |
| 理由を聞いたか | 聞いた・聞かなかった判断とその理由（`reasonDecision`）。理由の回答には、訳・解説・ヒントを見ずに答えたか（`reason.independent`） |
| 選択肢の順番 | そのとき表示した選択肢の順番 |
| 種類 | 初回診断 / 解き直し / 類題 / 確認問題 / 復習 |
| 選んだ理由 | 復習でその問題を選んだ理由（`pickWhy`、5-9）。復習以外は `null`、この項目ができる前の記録にはない |
| その他 | 問題IDと版、形式、確認する知識、日時、画面を見ていた時間、離れていた時間、追加した確認問題 |

「指定の形と違う」（例：to を使う条件で My dream is being a teacher.）は、英文として正しいかどうかを判定しません。
「採点保留」は登録された正答・誤りのどれとも一致しない答えで、誤りとは扱いません。どちらも先へ進めます。

### 5-2. 確認状況 ＝「これまでの確認実績」＋「いまの再確認の必要」
**自力正解**：不定詞の部分が正解・ヒントなし・解き直しではない・同じ学習回で解説を見たあとではない・「自信がない」なし。

これまでの確認実績（過去の事実。あとで間違えても消さない）
| ■ | 表示 | 条件 |
|---|---|---|
| 0 | まだ自力の正解なし | — |
| 1 | 自力で1問正解・追加確認前 | 自力正解が1問 |
| 2 | 別の問題でも自力正解 | 異なる2問以上で自力正解 |
| 3 | 後日の復習でも正解 | 2に加え、前回の回答から3日以上空けた復習で自力正解 |

いまの再確認の必要（最近のつまずき。条件を満たすまで残る）
| 表示 | 開く条件 | 解消する条件 |
|---|---|---|
| 最近の誤答あり・再確認が必要 | 不正解・「わからない」 | 別の学習回で、別の問題に自力正解 |
| 答えは正解・意味の再確認が必要 | 意味・理由の問いで違う選択、または意味の確認問題で誤り（訳を見たあとの誤りも含む） | 別の学習回で、別の問題の意味・理由の問いに、**日本語訳・解説・ヒントを見ずに**正解 |
| ヒントを使って正解・自力で再確認 | ヒントを使って正解 | 別の学習回で、別の問題に自力正解 |
| 自力で正解・本人は自信なし | 自力で正解したが「自信がない」 | その後、別の問題に自信がないの申告なしで自力正解 |

- 同じ学習回で解説を見たあとの正解は「解説後の正解」として記録しますが、再確認の解消には使いません
  （例：復習で誤答 → 直後の確認問題に正解 → まだ「再確認が必要」）。
- 同じ問題をもう一度正解しても解消しません（答えを覚えただけの可能性があるため）。
- 意味・理由の問いを間違えても、答えが正解だった事実（実績）は取り消しません。「文法を理解していない」とも表示しません。
  質問の読み違いもありうるため、訳なしの意味の確認問題で確かめます。
- 意味の確認の状態：「訳を見ずに確認できた」／「訳・解説を見たあとの回答のみ（参考）」／「再確認が必要」／「まだ確認していない」。
  理由を聞かなかった回答は、意味を理解した根拠にしません。
- 根拠は「同じ問題の解き直し」「別の問題・解説直後」「別の問題・自力」「後日の復習」に分けて「判定の根拠」に表示します。
- **講師に相談する候補**：最近の誤答が2回以上あり、そのうち解説を見たあとの誤答がある場合。
- 画面では「いまの状態」を1行で表示し、実績は■の数、詳しい根拠は「判定の根拠」を開くと見られます。

### 5-3. 復習予定（項目ごと）
学習回の終わりに、上の確認状況と同じ根拠で決めます（表示と予定が食い違わないように）。
| 状態 | 次回 |
|---|---|
| 最近の誤答・意味の再確認・ヒント使用が残っている | 1日後 |
| 「自信がない」が残っている | 今の間隔と3日の短いほう（長い間隔のままにしない） |
| 初回診断で全問自力で安定して正解 | 3日後（それ以外は1日後） |
| 類題・確認問題（解説のあと） | 今の間隔のまま（解説直後の正解では延ばさない） |
| 復習の1問目（解説を見る前）に自力で安定して正解し、意味の問いも違っていない | 間隔を1段階延ばす |
| 採点保留・指定の形と違う答えだけ | 今の間隔のまま（短くも長くもしない） |

- 期限切れが溜まっても1回は最大3項目。再確認が必要な項目 → 実績の低い項目 → 期限の古い項目の順。
- 復習で出す問題の選び方は 5-9。

### 5-4. 理由・意味の問いを出す条件
前提（すべて満たすときだけ候補）：類題・確認問題・復習である／問題に意味の問いがある／答えが正解／ヒントなし。
1回の学習で聞くのは `maxReasonQuestionsPerSession`（初期値3）問まで。

| 順 | 条件 | 聞く？ | 記録される理由 |
|---|---|---|---|
| 1 | 意味の再確認が必要な項目 | 聞く | meaning-recheck |
| 2 | 答えは正解だが「自信がない」 | 聞く | unsure |
| 3 | 最近の誤答を2回以上くり返している | 聞く | repeated-errors |
| 4 | 答える前に日本語訳を見ていた | 聞かない（訳なしの別の英文で確かめる） | translation-shown |
| 5 | 前回の「自信がない」「ヒントあり」が残っている | 聞く | recheck-pending |
| 6 | 訳なしで意味を確認したことがまだない | 聞く | first-check |
| 7 | 自力正解の実績がまだ少ない（異なる2問未満） | 聞く | insufficient |
| 8 | それ以外（実績が安定） | 聞かない | stable |

- 診断では聞きません。意味の確認問題・不正解の答えでも聞きません。
- 意味の問いに答えるまで、日本語訳・正答・正誤・解説は表示しません（あなたの答えを入れた英文と選択肢だけを表示）。
- 質問文は「空所に入れた語句は、この文でどんな意味を加えていますか？」など正答の語句を含まない形で、選択肢の順番も毎回入れ替えます。
- 復習の1問目（解説を見る前）は、訳なしで意味を確認していない項目では英文だけの問題を優先します。

### 5-5. 類題・復習で間違えたあと
1. その場で、選んだ答えについての短い説明と解説を表示
2. 同じ項目の別の問題を「確認問題」として1問追加（意味の取り違えなら、訳なしの意味の確認問題を優先）。
   確認問題の正解は「解説直後の確認」として記録し、時間を空けた定着とは区別する
3. 確認問題でもつまずいたら、それ以上追加せず「基本の説明」を表示し、次回へ引き継ぐ（講師に相談する候補になる）
4. 1回の学習で追加できる確認問題は2問まで（`maxFollowUpsPerSession` で変更可）。上限・別の問題がないときは、その理由を記録し、確認済みにしない
5. 「今日はここまで」でいつでも終えられ、出していない確認は「次回にもちこす内容」として記録される

### 5-6. 問題の版と過去の記録
各問題の `changes` に、版を上げた理由と過去の記録の扱いを書いています（画面の「問題の修正履歴」でも見られます）。
- 版1→2で理由の問いを作り直した問題：答えの正誤は有効、版1の理由の回答は判定に使わない（`reasonValidFrom`）
- `inf-p-v2`：版1は選択肢から答えを推測できたため、版1の回答は判定に使わない（`excludedVersions`）
- そのほか（指示・説明文の修正）：答えの正誤は有効
- 空所補充8問（版3）：版2までは正答だけが to で始まり、形の手がかりだけで選べたため、版1・2の回答は判定に使わない（履歴には残す）

### 5-7. データの保存
- 通常の記録とデモモードの記録は別の保存領域。デモモードを終えるとデモの記録は消え、通常の記録は変わらない。
- 通常の利用では日付操作を表示しない（設定 →「講師・開発者向け」からデモモードに入ったときだけ）。
- 旧形式の記録は、元データの控え（`ea-study-backup-schema1-normal`・`ea-study-backup-schema2-normal`）を残してから新形式に引き継ぐ。記録は削除しない。
  v2→v3 では、当時の出題形式から「答える前に日本語訳を見ていたか」を補う（空所補充・並び替え・日→英は見ていた、意味の確認問題は見ていない）。
  以前の開発用日付で作られた回答には印をつけ、判定から除外する。
- 保存データが壊れていたら、元データを控えに移してから始める。控えも作れないときは上書きせず、保存を止める。
- 保存に失敗したら画面上部に警告を出し、「保存しました」とは表示しない。

### 5-8. 英文構造の段階解説（試作）
- 回答を確定したあと、正誤の画面に「構造を見る」が出る。確定前・理由の問いに答える前は、構造・訳・解説を出さない。
- 段階は問題データの `structure.steps` で指定する（英文・強調する語句・役割・ラベル・説明文・骨格）。問題ごとにプログラムは書かない。
  語句が英文にない・重なっている・ラベルがない場合は `node tools/validate-bank.mjs` が知らせる。
- 色だけに頼らず、主語＝下線、動詞＝二重下線、説明のまとまり＝（ ）と破線の枠、補語＝点線、それぞれにラベルをつける。
- 日本語訳は「日本語訳を見る」を押したときだけ表示する。
- 開いた回数・見た段階・最後まで見たか・訳を見たかを、その回答の記録（`structureView`）に残す。
  **正解・理解済みの根拠には使わない**（確認状況・復習予定の計算はこの記録を見ない）。
- 試作の単元（`data/structure-trial.js`）は1問だけで、確認状況・復習予定には反映しない。単元一覧から試せる。

### 5-9. 学習履歴を次の復習に生かす（復習で出す問題の選び方）
`js/planner.js` の `reviewPicks`（問題ごと）と `dueReviews`（項目の順）だけで決めます。別の仕組みは作らないでください。
文法タグは問題の `skill`（項目）で、回答の記録の `skillId` に残ります。

**項目の順**（期限が来た項目が多いとき、1回最大3項目）：再確認が必要 → 「自信がない」が残る → それ以外。同じ区分では実績の低い順、期限の古い順。

**項目ごとの問題**（1項目2問）
| 順 | 選び方 | 記録される理由 `pickWhy` |
|---|---|---|
| 1問目 | 同じ理解を**別の問題**で確かめる：つまずいた問題・優先の理由がある問題「以外」で、しばらく見ていない問題（訳なしで意味を確かめていない項目は、英文だけの問題を優先） | `other-question` |
| 2問目 | 回答履歴で優先する問題：誤答 → ヒントで正解 → 意味の問いが違った正解 → 自信がない正解（同じ順位なら最近のもの） | `recent-error` / `hint-used` / `meaning-mismatch` / `low-confidence` |
| 2問目（優先する問題がない） | しばらく見ていない問題 | `oldest` |
| 別の問題がない | 項目に問題が1問しかないときは、その問題で確認する。「次回にもちこす内容」に理由を残し、同じ問題の正解では再確認を解消しない | `no-other-question` |

問題ごとの優先は、その問題の回答を古い順に見て決めます。次の回答では優先を変えません。
- 採点保留・指定の形と違う答え（判別できないため、誤答にも正解にも数えない）
- 解き直しの正解（答えを見た直後のため）
- 解説を見たあとの正解のうち、つまずいた日と同じ日のもの

別の日に正解すると、その問題の優先は外れます（別の問題の解説を見たあとでもよい。毎回同じ問題が出続けないように）。
これは「どの問題を出すか」だけのルールです。項目の確認状況と再確認の解消は 5-2 のまま（別の問題での自力正解が必要）です。

### 5-10. 日付が変わるとき
- 「今日」は端末の時刻の0時で区切ります（`EA.util.startOfDay`）。復習の期限は「その日の0時までに来たもの」。
- ホームを開いたまま日付が変わった場合は、画面に戻ったとき（表示の再開・フォーカス）に描き直し、その日の課題・予定・学習時間を出します。
- 学習の途中で日付が変わっても、その学習回は続けられます。回答の日時は答えた時刻で記録します。
