# 設計メモ（初期版）

## 1. 目的の理解
高校・大学受験に向けた英文法の基礎固めを、生徒が一人で進められるようにするアプリ。
「解説を読んで終わる」「すぐ忘れる」「選べても理由がわからない」「次に何をするか決められない」「復習しない」
を減らすため、**アプリが次の課題を出し、答えを見ずに思い出す機会を、日を空けて繰り返す**。
正解したことと理解したことを区別し、記録は講師がのちに確認できる形で残す。

## 2. 範囲
**初期版で作ったもの**
- 単元「不定詞（基本）」：〜すること／〜するための・〜すべき／〜するために（目的）の3項目
- 初回診断6問（空所補充2・並び替え2・日→英2）、全問回答後に結果と解説
- 解説（正答・訳・「どの部分がどの意味につながるか」）→ 解き直し（同じ問題）→ 類題（別の問題＋理由の選択）
- 意味の確認問題（「何のために」「どの言葉を説明」など、文法用語なしで問う）
- 「自信がない」「ヒントを見る」「わからない」、途中終了と再開
- 確認状況（4段階・根拠つき）、復習予定（ルール）、復習テスト、履歴・復習一覧、問題ごとの過去の回答
- 開発用の「日付を進める」、記録の書き出し（コピー）

**後回し**：正誤判断＋理由選択の問題形式、ほかの単元、講師画面、ログイン・サーバー、AI、音声、長文、ランキング等。
「英定義」は仕様未定のため何も実装していない。

## 3. 技術構成と理由
- **ビルド不要の静的Webアプリ（HTML・CSS・素のJavaScript）**
  - iPad の Safari でリンクを開くだけで動く。アプリストア申請やインストールが不要。
  - 将来スマートフォン・PCでも同じものが使える。
  - 部品が少なく、開発者が替わっても読みやすい。
- **保存は端末内（localStorage）**。サーバー費用ゼロ・ログイン不要で試せる。
  - 限界：端末・ブラウザ間で共有されない／Safariのデータ消去で消える／講師がリアルタイムに見られない。
  - 対策：設定画面から記録を書き出して（コピー）講師に送れる。
- **問題データはプログラムと分離**（`data/infinitive.js`）。`node tools/validate-bank.mjs` で形式チェック。
- 外部サービス・APIキーは使っていない（Google Fonts の文字だけ。読めない場合は端末の文字で表示）。

## 5. 判定ルール（すべてルールのみ、AIなし）

### 採点結果の種類
| 結果 | 意味 | 確認状況での扱い |
|---|---|---|
| ○ 正解 | | 正解 |
| ○ 不定詞は正解（ほかに小さな直し） | 例：to be teacher（a がない） | 正解 |
| △ 別の正しい表現 | 例：My dream is being a teacher | 正解にも誤りにも数えない |
| ？ 判定保留 | 登録された正答・誤りのどれとも一致しない | 正解にも誤りにも数えない |
| × 不正解 | 選択・並び替えの誤り、登録されたよくある誤り | 誤り |
| — 「わからない」 | | 誤り |

### 記録の種類（attemptType）
初回診断 / 解き直し（解説直後に同じ問題）/ 類題（別の問題）/ 復習（後日）。
各回答に、問題IDと版・形式・確認する知識・回答・結果・自信の申告（「自信がない」か「申告なし」）・
ヒントの使用・理由の選択・開始と回答の日時・表示時間・画面を離れていた時間を記録する。

### 確認状況（アプリ内での確認状況。習得の保証ではない）
| 段階 | 条件 |
|---|---|
| まだ確認が足りない | 正解がまだない |
| ヒントや解説があれば解ける | ヒントあり・解説直後の解き直し・「自信がない」での正解、自力の正解が1問だけ、または直近が誤り |
| 別の問題でも自力で解けた | 2つ以上の**異なる問題**で、ヒントなし・自信がない申告なしで正解し、直近が誤りでない |
| 時間を空けても解けた | 上に加え、前回の回答から3日以上空けた**復習**で自力正解 |

解答時間は判定に使わない。問題に不備があれば `status: 'excluded'` でその回答を判定から除外できる。

### 復習予定（知識・技能ごと）
- 初回診断：自力で安定して正解 → 3日後、それ以外 → 1日後
- 類題（解説直後）：正解しても延ばさない。誤りがあれば1日後
- 復習：自力で安定して正解 → 次の段階へ延ばす／ヒント・自信がない・判定保留 → 同じ間隔／誤り → 1日後に戻す
- 復習の問題は「しばらく見ていない別の問題」と「前に間違えた問題」を組み合わせる
- 期限切れが溜まっても1回は最大3項目。確認状況の低い項目から出し、残りは次回へ
- それぞれの予定が決まった理由は「履歴・復習」で見られる

## 6. AIの組み込み方（将来）
- 問題選び：`js/planner.js` の `buildPracticeSession` / `buildReviewSession` を置き換える
- 誤答原因の推定・解説の調整：採点結果（`feedback`）と解説の表示部分に追加
- 講師向け要約：書き出しデータ（回答履歴）を入力にする
- **APIキーはブラウザに置かない**。サーバー（または中継用の小さな関数）経由で呼ぶ。
  Claude など外部AIの利用は、呼び出し回数と文章量に応じて費用が発生するため、導入前に用途と費用を見積もる。
- 復習日程と記録はルールのまま管理し、AIの出力は「提案」として扱う。

## 7. 今後の段階
1. **塾での試用（今の段階）**：端末内保存、1人1台
2. **講師連携の準備**：ログインとサーバー保存（例：Supabase / Firebase などの認証つきデータベース）。
   `js/storage.js` を差し替え、生徒ごとに記録を集める。無料枠を超えると月額費用がかかる
3. **講師画面**：課題指定、苦手・改善の確認、判定根拠の確認と修正、指導記録
4. **学習内容の拡張**：単元追加、過去の文法の織り込み、長文、音声 など

## 8. 確認の状況
- 自動テスト（`npm run check`）：採点・確認状況・復習予定・問題選びのルール 12項目
- 通しの確認（`npm run e2e`）：iPad相当（横・縦）とスマホ幅のブラウザで、診断→解説→類題→まとめ→
  再読み込み→日付を進めて復習 まで。途中の再読み込みからの再開、ドラッグ操作、横スクロールなしも確認
- 実機のiPad（Safari）での確認は、開発環境からはできないため未確認
